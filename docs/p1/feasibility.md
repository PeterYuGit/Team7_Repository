# P1 Section 2.6 Feasibility Summary

| Feasibility gate | Verdict | Evidence behind the verdict |
|---|---|---|
| Technical | Feasible | FR-01 to FR-15 cover form input, basic classification using the assumed thresholds in Table 3.1, inspection workflow displays, and record keeping; neither AI image processing nor carrier integration is required. All of us have built a full-stack app before with database storage. The only aspect that would be uncertain is obtaining the weight from the USB scale in FR-01. Spike-01 will be able to answer that, while the fail-safe for FR-02 is manual entry. It is a no if there isn't a computer interface available on the scale of the bookstore and manual entry is not an option. |
| Operational | Feasible, conditional | The system adds to an existing step rather than creating a new process. It would be a no in a scenario where either the bookstore would not implement our thresholds or there is no one available to act as the inspector. Both situations remain assumptions (Q1, Q2). |
| Schedule | Feasible | P1 to P3 are established deadlines for the course, with P2 focusing on design instead of coding. The functional requirements are recorded in Section 3.1 (FR-01 through FR-15). Milestones and responsibility segments can be found in Section 4.2. The answer would be no if new features are added which lead to a change in the scope as defined in Section 1.2. |
| Economic / resource | Feasible | Development: 7 listed team members; effort estimates for P3 require team confirmation. Operation: the existing station computer is assumed under C3; additional operating costs have not been estimated. Maintenance: no maintenance planned after the course. Opportunity: no time spent on other coursework. Benefit: fewer broken books and discarded packaging according to claims, not measurement. Tools: GitHub and free tools. |
